# Task 12 — route/component mapping memo (12.0)

First deliverable of Task 12 (`fix-task-production-readiness-v3.md`), PR group 12-A.
Enumerates the spec's screens/behaviors against the as-built routes and components,
so the rest of 12-A/B/C adds only what's verifiably missing — no route-tree rebuild,
no re-architecture of what already works.

As-built routes: `woreda.credentials.tsx` (layout), `.index.tsx` (queue),
`.new.tsx` (intake), `.$requestId.index.tsx` (detail/stages 2-4,8 + exceptions),
`.$requestId.print.tsx` (stages 6-7), `.verify.tsx` (public lookup, out of scope
for staff-facing stages), `admin.credential-template.tsx` (super-admin template
editor, out of scope for stage UI).

## Print layout (12.2)

- ID-1 85.6×54mm, both faces, `@media print` isolation, react-to-print: **already built and correct** (confirmed dimensions/print-CSS in `.print.tsx`).
- A4 certificate variant for archive: **missing**, not found anywhere in the print route.
- `sanitizeLetterHtml` parity between preview and print: applies to `letterTemplate.ts` (service letters), not the credential card template — credential template rendering doesn't go through HTML sanitization at all (it's a positioned-field canvas, not HTML), so this specific F-09 tie-in doesn't apply to credentials the way it does to service letters. Noted so it isn't chased as a false gap.

- Filter chips: kebele/status/date-range filters exist in `.index.tsx`; officer filter and request-type filter need verification/addition.
- Waiting-duration-per-row (from `credential_status_history`): **missing**.

## Offline (12.4)

**No offline infrastructure exists anywhere in this app** (repo-wide grep for `offline`/`navigator.onLine`/queue persistence came back empty except one unrelated hit in a barcode scanner component). This is a ground-up build for PR 12-C, not an extension.

## Hooks / data layer (12.6)

No per-domain typed hook file exists for credentials (`src/hooks/` has the pattern — see `useServiceTypes.ts` — but nothing for credential requests). All query/mutation logic currently lives inline in the four route files (7,024 lines total). 12-A extracts the listed hooks into `src/hooks/useCredentialRequests.ts` (or split by concern) following the existing `useServiceTypes.ts` shape: `woredaId`-scoped query keys, `staleTime`, typed row interfaces.

## Zod (12.5)

`woreda.credentials.new.tsx` already has a `formSchema` with two `.refine()` rules (prior-credential-required-unless-new, document-required-for-correction). Extending in place rather than replacing: add police-report-number-iff-stolen, fields-to-correct-iff-correction, bank-reference-iff-bank (payment form currently has no Zod schema at all — inline state), waiver-reason-iff-zero, printer-name/copies/reprint-reason (print route currently has no Zod schema either).
